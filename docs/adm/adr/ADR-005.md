# ADR-005: 统一 41-bit 微码 ISA 与 嵌套循环合成架构

## 1. 背景与问题 (Context)
随着 AIACC 进入工业级算子库交付阶段，原有的 RLE (Run-Length Encoding) 压缩已不足以处理复杂图像卷积（2D) 和多维 Tiling 的指令开销。硬件提供了 41-bit 胶囊化微码，支持 EMBED (7层循环) 和 INC (地址自增)。现需要明确编译器后端如何利用这些位宽受限（Budgeted）的特性进行位流封装。

## 2. 决策与思路 (Decision)
1. **位宽预算优先制 (Budget-Aware Packing)**：
   * 采用“静态控制偏移 (Static Header)”与“动态货物区 (Dynamic Cargo)”的布局。
   * **Bit 30-40** 为静态锚点。**Bit 0-29** 为业务载荷 (CODE) 与控制工具 (LOOPS, DLY, INC) 的竞争区。
2. **三级级联压缩算法**：
   * **L1**: LOOPS/DLY 线性压缩。
   * **L2**: INC 单层循环搬运合并。
   * **L3**: EMBED+INC_EMBED 多维循环拓扑折叠。

## 3. 算法与实现影响 (Algorithm Impact) [SE]
* **LIR Packer 更新**：需要能够识别 DFG 中的周期性偏移 (Stride)，将其转换为 $EMBED=0, INC=Stride$ 的循环指令。
* **物理冲突检测 (Conflict Shield)**：如果 $Payload + Header > 30 bits$，强制执行“先 NOP 占位 + 后指令加载”的拆分策略。

## 4. 替代方案建议 (Alternatives)
* **方案 A (固定位宽)**：若为每个字段分配固定位宽，会导致 `UR_WRITE` (28b) 指令无法携带任何 `LOOPS`，指令数膨胀。**被否决**。
* **方案 B (动态位宽)**：本文采用方案，极大提高了复杂算子的取指带宽效率。

## 5. 验证与门禁 (Verification) [TFD]
* **集成测试**：`test_lir_emitter_full_stack.py` 必须对 2D 卷积风格算子进行二进制真值比对。
* **物理审计**：`HSTSVerifier` 必须增加对 `EMBED_END` 的时序覆盖检查。
