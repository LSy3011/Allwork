# ADR-056 · V1 支持范围定义与受限通用准入规则

> **状态：修订稿 v4（用户批准进入实现，四项契约修正落下；hco M1–M5+notes 已在 v3 全落）。** 本稿核心命题（用户 2026-09-26 原话，逐字）：
>
> > **对受限的 fp32 逐元素公式，用户只新增配置；编译器自主判断是否可编译，生成单 stage 指令，
> > 自动完成 VCS 与独立语义验证，并交付明确的成功或失败报告。**
>
> 跨 stage 分段、矩阵类算子、更多基础操作、每算子上板**不在本 ADR 范围**，留在后续完善阶段。
> A1 已验收证据（ADR-055）的一切门槛原样沿用；本 ADR 不放宽任何既有守卫。

## Context

### 1. 为什么现在要这份 ADR

ADR-055 A1（2026-09-26 验收）拿到的是**点证据**：单一算子 `add`、两类槽形态
（II=2 单有效槽+气泡、双有效槽各一）在真 v4.22 RTL 上三规模全绿。它证明的是「展开协议在这两类
形态上成立」，不是「用户给一个未预置公式就能编译出可验证算子包」。

把点证据变成可交付能力，缺的三块恰好是用户 V1 主线①②③：范围没定义（用户不知道该写什么）、
准入是名称白名单（新公式进不去）、验证链没有统一入口（多脚本手工串）。本 ADR 同时定义①和②，
③④以本稿口径直接实现，不另立 ADR（纯工具整合、无流水线接口语义变化）。

## §A. V1 支持范围定义（D56-1）

### A.1 分层划界

| 层 | 范围 | 依据 |
|---|---|---|
| **用户公式层** | 逐元素 fp32 表达式：张量输入（stride=1）×标量参数（stride=0 驻留），经 **加法 + 乘法** 的有限组合构成**单输出**式；无副作用、无归约、无向量内跨元素引用 | 基础操作集 = {fpadd, fpmul}，二者均有 VCS RTL 证据（add A1 / mul M1） |
| **后端支撑路径** | 已验证的 UR 读写、VIN/VOUT、RtoVR 致密集路由与 ADR-053 绕行约束；**沿用已验证连接**，不因「需要 RtoVR」就把未验证连接集合一并纳入 | ADR-053/054/055 证据链；census 显示绕行 pass 下其余连接形态未被任何非 embed 流验证 |

### A.2 范围的具体条款

1. **语法子集**：运算符 ⊆ {`+`, `*`}；函数调用、幂、除法、二元减法、比较/选择全部范围外。
   **一元取负区分两种情形**（用户定夺）：
   - **负的 fp32 常量字面量允许**（如 `x + (-2.5)`、系数 `-3.0 * x` 中的字面量 `-3.0`）；
   - **对表达式取负拒绝**（`-x`、`-(x+y)`、`-alpha` 均范围外，诊断 `SYNTAX_UNSUPPORTED`）。
   - 判定时机 = **原始语法树阶段**（文本 → AST 时，SymPy 改写之前）：SymPy 会把 `-x` 规整为
     `Mul(-1, x)`，改写后字面量与取负不可区分——故须用文本级 AST（如 Python `ast.parse`）
     检出 `UnaryOp(USub)` 且其操作数**非数值字面量**者即拒。
   - **一元正号 `+x`（`UnaryOp(UAdd)`）允许**（hco notes-3 要求成文）：对 fp32 位模式恒等，
     在 §C.4 域内无改变语义的情形。
2. **基础操作集**：lower 后计算节点单元 ⊆ {FPMUL, FPADD}；出现任何其他计算单元（LOGIC 等）即范围外。
3. **数据类型**：fp32 仅。
4. **布局**：YAML `tensors:` 显式声明（bank/role/offset/length，schema 为 `ops/add.yaml` 的
   超集——新增 `length` 见 §F.5）；输入张量逻辑 stride=1、参数 stride=0、输出单写口。
   布局冲突（bank 重叠等）→ 诊断。
5. **规模**：合法规模集合 `n_rows ∈ 4·ℕ⁺`（vec4 打包，num_iterations = n_rows/4 必须为整数）；
   单 stage；每队列展开行数 `L_q = II·R_q + 2 ≤ 128`（以**最终产物实测**为准）；
   `R_q` 公式沿用 ADR-055 §2（含 `eff_num_iter` 来源限定）。
6. **范围承诺的写法**：V1 **不承诺**「范围内一切公式必能编译」，承诺「范围内输入**要么**编译成功
   并交付全绿验证报告，**要么**交付分类明确的失败诊断（§D.2）」——「编译器自主判断是否可编译」
   的落点就是 §B 的静态准入层。

### A.3 非目标（明示）

跨 stage 分段（A2a）、矩阵/归约/移位类结构（A2b）、除 fpadd/fpmul 外的用户层算子、HBM 全路径
（M3）、全自动内存分配、每算子上板、性能优化。8-UNSAT（census 未解出者）仅在**阻塞本主线**时
深查，不预占。

## §B. 受限通用准入规则（D56-2 / D56-3）

### B.1 三层模型

| 层次 | 含义 | 实现载体 | 失败行为 |
|---|---|---|---|
| **L1 配置请求** | 用户在 YAML 声明**请求**尝试展开路径 | 新字段 `experimental_unroll: true`（缺省缺席 = 未请求）。**语义仅是请求，不构成能力证明** | 缺省算子维持现状行为；V1 交付入口对未请求算子直接拒绝受理 |
| **L2 静态准入** | 编译器对请求算子执行全部结构性检查 | §B.2 闸门清单，assembler 判定点 | 任一闸门不过 → **明确拒绝**：非零退出 + 分类诊断 + **不产出交付包**（§F.3 发布制） |
| **L3 验证结果** | 该公式·该配置·该规模是否实际通过全部验证 | §D 一键链输出 verdict | 任一红 → 失败报告（含分类），不交付算子包 |

三层**正交**：L1 过≠L2 过；L2 过≠L3 过；L3 全绿才允许进入「已验证算子包」清单。
四档覆盖口径沿用既有纪律（可调度/可发射/VCS/上板分列，禁止越档表述）。

### B.2 L2 静态闸门清单（全是结构性检查，与算子名无关）

1. **G-op**：DFG 计算节点单元 ⊆ {FPMUL, FPADD}（A.2-2 的 assembler 侧复核）。
2. **G-II**（hco M1 修订，与代码现态对齐）：`iq_II ≥ 2` → 进入展开分支闸门链；
   `iq_II == 1` **且单槽且非 smi-ds-t** → 分流 ADR-054 平坦压缩分支
   （`assembler.py:314` 条件 `len(kernel_map)==1 and not is_smi_ds_t_dp and iq_II==1`，
   mul 已证路径，报告中注明走了平坦路径）；`iq_II == 1` 其余形态（多槽或 smi-ds-t）→
   与现态一致**响亮拒绝**（`assembler.py:363-366` 出口）——**不得按旧措辞设想为
   「II<2 一律分流平坦」**。
3. **G-slot**：kernel_map 构造无槽冲突（ADR-055 D1，`assembler.py:285-294` 既有）。
4. **G-stride**：`stride≠0` 子集内步长一致（ADR-055 errata I1 现形，**不得**回退为 v3 行文的
   「全 IQ stride 相等」——会与 add ur-r3 {α 驻留, x 步进} 正面冲突）。
5. **G-addr**：地址规则——FILL/DRAIN 受控允许、LIVE 越界拒绝（§F.5 成文定义）。
6. **G-cap**：容量构造预测全线 ≤128 且**产物实测**复核（ADR-055 D3，`assembler.py:465-474` 既有）。
7. **G-stage**：单 stage（出现任何 stage 切分需求 → 拒绝，诊断指向 A2a）。
8. **G-dp**：`is_smi_ds_t_dp` 出现 → 拒绝（沿用 `assembler.py:359-362` 现有拒绝）。

任一闸门失败 → `STATIC_ADMISSION_REJECTED`。**禁止任何「失败即回落 embed」兜底**
（ADR-055 D1 铁律原样生效）。

### B.3 兼容语义（含 add 迁移，用户修约①）

- **add 迁移为显式请求**：`ops/add.yaml` 增补 `experimental_unroll: true`。迁移**前后产物
  必须零字节一致**——沿用 mul 零字节审计方法论：迁移前归档现产物基线 → 迁移后重跑三规模
  e2e → 双向 byte-diff 为空。迁移本身只是从「名字命中白名单」改为「字段显式声明」，语义等价
  由该比对证明；不一致 = RED，定位修复，不放宽。
- 其余 35 份未声明字段的 YAML：**行为逐比特不变**（mul/fma 走 flat、其余现状 embed 主线），
  由新增契约测试锁定。它们可以继续出现在旧流程（census、sim 自洽比对），**但 V1 交付入口
  只受理 L1+L2 全过者**；旧路径产物一律不得出现在「可交付算子」报告中。
- 名称归一化与双向响亮失败（pipeline_runner M2/M3）语义原样保留——判据从「名字 ∈ 白名单」
  换成「YAML 声明了请求字段」；归一化失败的拒绝路径不变。

## §C. 独立参考语义（D56-4，用户修约②——本方案最需补严处）

### C.1 命题

「用 NumPy 对公式求值」只保证**独立于发射器**，**不保证**数值语义对应 RTL。参考端必须检验
**用户公式的既定语义**，不能复用编译器 lowering 后的结果来定义「正确答案」（否则是自我循环）。

### C.2 有序语法树 + 参考自动生成（用户修约②）

- **从原始公式文本建立有序语法树**（§A.2-1 同一 AST 工序的下游产物），保留用户书写的
  运算顺序与结合性；**编译端 lowering 与参考端求值都从该树出发**，共同遵守其顺序语义。
- **禁止未经证明的重关联/交换/合并**：任何相当于重排浮点运算顺序的变换，除非先对该公式
  在该输入域内证明逐位等价（V1 默认不做等价变换）。
- **逐步参考自动生成**：由有序语法树机械展开为逐步 fp32 语句序列——每个内部节点一条
  `tmp_i = fp32(op(lhs, rhs))`，按拓扑序以 numpy float32 执行。**不要求、也不允许**为每个
  新公式手写参考程序（手写本身是错误源）；生成器单一、可审计、带自测。
- 对首选公式，生成的参考规格逐字为：
  `t = fp32(x + other)` → `y = fp32(alpha * t)`（IEEE-754 binary32，round-to-nearest-even，
  每步独立舍入，禁止 FMA 融合）。
- SymPy 仅作结构分析与规范化记录（§E.2-2），**不作为数值参考的执行器**。

### C.3 golden 来源核对与参考发生器锚定（hco M3）

- **来源已实锤**（hco 2026-09-26 回源）：现行链路 golden = Python simulator 终态 dump
  （`sim/smc_simulator/tools/physical_runner.py:143-144 dump_banks` →
  `package_vcs_case.py:15` 以 output_bank 为 golden 侧）。§C.2 参考发生器替代其产生
  golden；核对与处置写入验收报告。三区比对「T 区差分不经编译器产物」性质保持。
- **发生器自身锚定（验收前置）**：参考发生器的第一个服务对象是新公式，出错无人发现——
  故其**先对 add 公式**（三规模 8/60/4）输出 golden，与现行 sim 中转 golden **逐位一致**，
  不一致即 RED；锚定通过后方允许用于 scale_sum 及后续公式。锚定证据归档。
- **发生器舍入自测（用户裁示③，与 add 锚定并列为验收前置）**：发生器须自带
  **固定预期位模式**的小用例集，至少覆盖——① 加法与乘法的舍入（RTNE 平局进位、
  不同量级相加的舍入）；② **会因重关联而改变 binary32 结果的表达式**（两种求值顺序
  产生不同位模式，验证发生器严格遵循有序树顺序而非代数等价顺序）；③ **有符号零**
  （+0/−0 的产生、传播与比较语义）；④ **亚正规、溢出、非有限值的拒绝**（域外数据 →
  响亮失败，不静默求值）。**参考端保持独立于 lowering 与 simulator**（不 import 编译器
  lowering 内部、不以 simulator 产物定义正确性）——这样才足以承担新公式的正确性判定。

### C.4 输入数值域（v4 用户拍板定稿：采纳 hco 允许域与双道 AND，并修正直接冲突）

**允许域**：`D = {+0, −0} ∪ { v ∈ binary32 : 2^(−126) ≤ |v| ≤ (2−2^(−23))·2^127 }`——
排除 ±inf、NaN、**全部亚正规**；±0 允许。**输入、常量、每一步运算结果均须在 D 内。**
排除亚正规的理由成文（hco）：RTL FPADD/FPMUL 的 flush-to-zero / 亚正规支持**从未被验证**
（现有 VCS 证据全部来自 [−10,15] 量级数据），V1 域内规避该未证行为比验证它便宜；
后续放宽须先补 RTL FTZ 行为专项。

**直接冲突的成文修正（用户 2026-09-26 指出，v3「采样域默认 |x|≤2^16」撤回）**：
按静态区间规则，**add 既有采样域会被拒**——`alpha·other`：2.5×[−5,15]=[−12.5,37.5]；
`x+alpha·other`：[−10,10]+[−12.5,37.5]=[−22.5,47.5]，该区间与亚正规带相交且非可证
单点 {0}。`|x|≤2^16` 仅是幅度上限，既不能排除输入亚正规，也不能解决混合号抵消——
**不得作为静态通过的依据**。

**第一版落地规则（用户裁示）**：

1. **保留保守双道 AND**：静态无法证明安全就拒绝；诊断文案明确写明这是**保守拒绝，
   不代表实际输入必错**（并建议缩小采样域）。
2. **scale_sum 首验使用可证安全的明确区间**：`x, other ∈ [1,2]，alpha = 2.5`
   （传播：`x+other ∈ [2,4]`，`alpha·(x+other) ∈ [5,10]`——全正规、不与亚正规带相交、
   无溢出，静态可证安全）。`scale_sum.yaml` 现档 `test_data`（[−10,10]/[−5,15]）是
   预检遗留，在数值检查实现时同步改为安全域；**未经 §C.4 双道通过的装载数据不得进入
   V1 首验交付链**（调度结构与数值范围无关，§E.3 预检结论不因域切换失效）。
3. **add 原有三规模数据（[−10,10]/[−5,15]/α=2.5）保持原样**，用于回归与参考发生器
   锚定（§C.3）；**另加安全数值域用例验证 V1 准入绿路径**（scale_sum 首验安全域即其一；
   add 形态的绿路径准入如需演示，以**新加的 add 安全域变体**承担）。
   **不得改动旧基线来让新闸门通过**：add 遗留数据在新静态门下的保守拒绝判定如实记录，
   其回归证据身份（零字节、逐比特不变、发生器锚定）不依赖该判定为绿。
4. **区间传播实现规格**（「每节点向外 1 ulp」**不得**称为完整的 IEEE 区间算法）：
   实现须明确定义——① 端点承载精度与端点运算方式；② 向外舍入包络的精确定义
   （向哪个方向做 nextafter 扩展、RTNE 边界如何外扩）；③ 精确零处理（区间恰为单点
   {0} 的可证条件与 ±0 符号语义）；④ 跨越 ±FLT_MAX 的溢出处理；并以单元测试证其
   **保守性**（任意输入点的精确逐点结果必被传播区间包住）。
5. **实际数据检查同时确认数据属于声明区间**：装载数据逐点核验 ∈ `test_data` 声明域
   ∧ ∈ D；数据发生器加装前域内过滤，**越域样本立即响亮失败而非裁断**。

**检查工序＝双道 AND（两道都过才算过）**：

- **(a) 编译期静态区间传播**：对 §C.2 有序语法树逐节点做保守区间传播（规格见上第 4 条；
  输入区间为声明采样域）。拒止规则：任一内部节点区间越出 ±FLT_MAX → 溢出拒；区间与
  `(0, 2^−126) ∪ (−2^−126, 0)` 相交且不能静态证明恰为单点 {0} → 亚正规风险拒。
  常量/参数装载前先 RTNE 舍入为 binary32，舍入后须在 D 内。
- **(b) 装载数据逐节点核验**：§C.2 参考发生器在**实际装载数据**上对有序树逐步执行
  （与 golden 产生同工序），逐节点精确判定在 D 内——无区间保守性，是实际数据的完备判定。
- 静态道失败但动态道通过 → **仍拒**（保守拒绝，不代表实际输入必错）：把验收从
  「采样碰巧安全」提升为「采样域内可证安全」。「全正数相加溢出」由 (a) 溢出规则覆盖；
  「混合号抵消至 0/亚正规」由 (a) 亚正规规则覆盖；「仅查 test_data.range 不充分」
  由 (b) 闭合。

**失败行为**：`TYPE_LAYOUT_UNSUPPORTED`；诊断必带语法树节点路径与区间记录；不假绿。

**v4.1 勘误（2026-09-28，步②复核发现并即刻修复；两处均为实现期暴露的契约缝隙，

### D.3 逐拍裁决：期望先行，常数独立论证后冻结（用户修约③）

- **期望先由调度 + 显式协议延迟模型生成**（`compiler_schedule.json` 的 t/II + 延迟模型），
  再与 trace 比对；**禁止**「从 trace 读出常数当期望」的循环。
- 延迟模型的常数（`l_init` 族）来源：A1 实测族（add，断言*形式* 与恒等命题归属 A1 证据）
  + RTL 静态推断。**首次在新算子上探索得到的常数，必须独立论证**（由 RTL 文本/不变量推导，
  非由被验 trace 读取）**并冻结**进工具配置后再作先验断言；trace 与冻结值不符 →
  `PER_BEAT_PROTOCOL_MISMATCH`，不得回改常数拟合。
- (i)–(iv) 断言形式与 `TERM = l_init+1+II·R_q` 保留；「垫拍与槽数无关」是 A1 已证结构命题，
  新队列继承该命题，常数值须经冻结机制确认。
- **冻结清单（枚举）与载体**（hco notes-1 + 待决项②意见）：冻结对象 = ① INIT 垫拍公式
  `l_init = skip·II + 1`（+1 来源 ADR-055 M7）② TERM 相位公式 `l_init+1+II·R_q`
  ③ 残尾取指 `__probes` 语义 ④ (i)–(iv) 断言形式。载体 = **tools 侧版本化注册表**
  （协议模型常数、非硬件事实，**不放** hw_config）；每条记录 = 名称 / 值或公式 /
  RTL 推导出处行号 / **已证形态边界**（A1 仅证 II=2 两类槽形态）+ sha256，
  **先于**首次验收运行入库。新形态上的首个常数值只能走「探索 → 独立论证 → 追加冻结」，
  不得直接引用已有冻结值。
- **对称规则**（hco）：除「trace 不符不许回改常数」，同样**不得通过改动 schedule 侧输入
  拟合**；同一验收运行内 schedule 一旦变更，视为全新运行记录（期望随动重生成，
  旧记录归档不删）。

- **布针枚举三族实例层级**（tb:2442-2485 现探针属第一族）：平铺显式实例
  `dut.u_smi_top.u_iq_0..27/92/93`、generate 域 `gen_iq[28..66].u_iq`、
  `gen_iq_bridge[68..70].u_iq`；**stub 位（67、71-91，无 smi_iq 实例即无四信号）显式排除
  并记录**；枚举表由工具自动生成并与 smi_top 实例核对，**漏针即测试设施自身 RED**
  （「全部 IQ」工程口径 = `SMI_IQ_CNT=94`（smi_top.v:21）减 stub）。
- **cycle 域**：TB `iq_probe_cycle`（复位起 0、每拍 +1，tb:2453-2458）为公共锚；
  调度侧相对 t 的对齐 = 每队列首个 FETCH（现行 checker 做法）+ `l_init` 相位断言。
- **共同启动锚下的跨队列相位检查（用户裁示④-a）**：每队列首个 FETCH **仅用于队列内
  对齐**；还须保留**共同启动锚**（复位后公共 cycle 基准，由全局监测提供首个活动拍）
  下的跨队列相对相位检查——否则整条队列的平移错位会被队列内对齐操作掩盖。
  对齐只允许补偿公共基准的固定相位差，不允许逐队列独立平移后宣布一致。
- **写侧事件级检查与 FILL/DRAIN 隔离证据（用户裁示④-b）**：三区终值一致**不能**证明
  「没有非目标写」，也**不能**单独证明 FILL/DRAIN 不影响 LIVE。必须落实写侧事件检查：
  观测到的每个写事件投影回调度侧的写依赖集合（事件 ↔ 调度写依赖逐一对应，
  **无对应调度写依赖的写事件 = 违例**）；FILL/DRAIN 隔离逐拍检查——FILL/DRAIN 拍的
  读出产物不得出现在任何 LIVE 消费链的事件投影中。三区终值比对降为**补充**手段。
- 探针/监测工作在**新公式 VCS 之前**完成并自验；§E 预检已完成（见 §E.3 回填）。

## §E. 候选公式与预检（D56-7）

### E.1 首选：**`y = alpha * (x + other)`**（配置名订为 `scale_sum`；逐元素 fp32，vec4 打包照旧）

张量集与 add 同构：x(bank0, stride1)、other(bank1, stride1)、alpha(bank3, param, stride0)、
y(bank2, out)，另含 `constants`(bank7, role=constant) 常驻条目（两份 YAML 均有，
hco notes-2）——即同名同布局公式对换根算子。**措辞铁律**：「输入种类和逻辑步长与 add 相近；
**实际队列集合、槽占用、II 和相位由编译产物确定**，不作先验认定。」表达式树改变可能影响
CSE、路由、端口分配、调度与填充——全部以预检和产物为据。

### E.2 「未预置」核查三件套（新公式准入档案，逐字填报）

1. **原始公式文本**（用户所写，保留运算顺序）。
2. **规范化记录**（SymPy srepr 的结构记录 + §C.2 有序树一致性比对——记录的是顺序**证据**，
   不是允许 SymPy 改动顺序）。
3. **与全部既有 YAML 的差异清单**：结构 diff——候选根算子为 Mul、add 为 Add
   （`Add(x, Mul(alpha, other)) ≠ Mul(alpha, Add(x, other))`），与 addcmul/horner_v3 等逐一对照；
   **代数等价不得当逐位等价**。

### E.3 预检（只读，不改发射行为；与 hco 审查并行）

用既有 census/预检同族方法（get_dfg + D4 绕行 pass + solve）跑前端+调度：产出 II、队列清单、
每队列槽占用/R_q/L_q **预测**（标注预测性质），归档仓库内。预检产出直接决定实验范围：

- II=2 → 落在 A1 已证形态邻域，按 §F 验收推进；
- **II>2 → 未证槽形态**（展开规则可能要修订）：允许继续作为推广验证目标，但**修订 + hco
  复核 + 全量回归计入工作量，禁止按「一轮即可通过」估时**。
- 备选第二公式（验收通过后）：`a*x*x + b*x + c`——按文本树为 **3 次乘法、2 次加法**
  （`a*x*x` 两次 + `b*x` 一次）；Horner 改写 `(a*x+b)*x+c` 可省一次乘法但**改变浮点运算
  顺序**，违反 §C.2 保序——V1 下以用户文本树为准。该公式考「同队双计算槽」。

### E.3-回填（2026-09-26 预检实测结论；归档 `verification_v2/artifacts/precheck_scale_sum_20260926/`）

- **II=2 SAT**（MII=2，res 贡献 VIN0）；**16 队列集与 add@preflight 逐名相同**（双向差集为空；
  遵守 preflight-16 vs census-17 不混引纪律）；槽形态多重集相同——双有效槽 ×3
  （rtovr-14 span3 / ur-r0 span2 / vin0 span2）+ 单槽 ×13，**全部落在 A1 已证两类包络内，
  本稿「II>2 修订展开规则」预案不触发**。
- 预测总行 n8/n60/n4 = 110/526/78（与 add 实测值逐一相同，同构旁证，仍属预测）；
  束缚队列 rtovr-14：`2·N_eff+8 ≤ 128` → **预测 n_max^IQ = 240**（布局界 1024，IQ 界先到达，
  §F.2 边界成功用例可落 n_rows=240）；束缚队列与 add 不同（add=ur-r3、256 拒），两界不得混用。
- **首验新面（VCS 的真正考点）**：① **fpmul 收尾出 vout0 写回路径**（rtovr-16/35/ur-w0——
  add 是 fpadd 收尾，该数据连接 add 未行使过；队列/槽形态在包络内，连接是新的）
  ② **晚槽驻留 alpha**（ur-r0 晚槽 t=7 是 stride=0 alpha，r_k=2，填充=重复读 addr0；
  stride-1 other 占早槽 r_k=0 无填充）——**A1 的 254/255 环绕填充形状在本公式不会出现**
  （该证据保持 add 独有）③ golden 来源实锤为 sim 终态 dump（§C.3），参考发生器替换与
  add 锚定是 V1 验收前置。
- 预检入口顺带实证 §B.3 兼容语义：无 `experimental_unroll` 字段 → 16/16 队列走 embed 主线
  （branch_report.json 逐字），旧默认路径对新配置可用、非静默回落。
- **v4 注**：预检用 `test_data` 范围为遗留值；首验装载域按 §C.4-2 改为 `x, other ∈ [1,2]`
  （α=2.5 不变）。调度结构与数值范围无关，本回填全部结论（II=2、队列同构、n_max^IQ=240、
  首验新面三点）不因域切换失效。

## §F. 验收门槛（D56-8）

1. **三规模功能**：n_rows ∈ {8, 60, 4}（合法规模集合 4ℕ 内，与 A1 可比口径；若任何边界
   n_max < 60，改为边界内三档并记录理由）——原生 COMPARE **bit-exact** + 三区零违例 +
   逐拍 (i)–(iv)（§D.3 冻结常数）+ §D.4 flat ISSUE 层逐拍断言（G-II 分流的 II=1 算子适用时；
   hco M4）+ **共同启动锚下跨队列相位检查** + **写侧事件↔调度写依赖逐一对应 +
   FILL/DRAIN 隔离逐拍证据**（§D.4，用户裁示④）+ §C 独立参考 bit-exact。
   **容差收紧（用户裁示）：验收目标是 bit-exact；FP32-RELAXED 容差输出仅作诊断展示，
   一律不计入任何门槛通过。**
2. **容量边界用例（IQ区与布局区分别测试）**：
   - 合法规模集合 `n_rows ∈ 4·ℕ⁺`；
   - 分别计算 **IQ 容量界**（n_max^IQ = max{ n ∈ 4ℕ : ∀q, L_q(n) ≤ 128 }，由预检最大约束队列
     槽结构反解）与 **布局/数据容量界**（各 tensor 声明区长度的最小可得 n 上限）；
   - 先到达的边界定档跑通；**若布局边界先于 IQ 边界，不得强行要求该公式完成 IQ 容量边界的
     成功用例**——边界成功用例落在先到达者上，另一边界以预测+拒绝用例佐证并记录。
3. **超限一档拒绝 + 发布制（用户修约⑥）**：边界上一档运行 → 明确拒绝
   （`STATIC_ADMISSION_REJECTED`/容量诊断）。**交付发布制**：每次运行在独立目录
   （如 `build/v1_runs/<op>/<ts>/`）；**全部门槛通过后才发布**交付包至交付路径；
   失败运行保留全部诊断材料于其运行目录，但**不发布、不更新交付路径、不残留形态上
   可被误用为成功包的新交付包**。「失败不更新交付目录」由契约测试锁定。
4. **回归**：add 三规模全门槛 + add 迁移零字节（§B.3）+ mul 零字节 diff + mul VCS 回归
   + pytest 全量 + census 零误报。`experimental_unroll` 缺席算子行为逐比特不变由契约测试锁定
   （§B.4-5/6）。**add 回归基线（三规模指令产物 + golden + 装载数据）按现值原样冻结、
   sha256 归档（实现步①），后续一切回归比对只与该冻结基线比，不得重生成基线。**
5. **wrap 与地址规则成文**（用户修约⑤）：
   - **定义（v4 修正：分离展开重复序号 p 与逻辑迭代号 j——v3 两式在 r_k≠0 时不相等）**：
     `p` = op k 在展开序列中的重复序号；`r_k = ⌊t_k/II⌋ − skip_iterations`（op 在队列内
     的驻留槽位阶，沿用 ADR-055 符号）；**逻辑迭代号 `j = p − r_k`**；LIVE 消费区间 =
     `0 ≤ j < N_eff`（`j<0` = FILL，`j ≥ N_eff` = DRAIN）；第 p 次重复的烘焙地址
     **`addr(p) = (orig_offset + stride·(p − r_k)) mod depth`**（LIVE 内即
     `orig_offset + stride·j`；FILL 负偏移经 mod 环绕，A1 的 254/255 即此）；
     **张量声明区** = `[offset, offset + length)`。
   - **`length` 语义（hco M5 补全）**：单位 = **bank 内 UR word**（UR_READ/WRITE 地址域为
     8-bit word 单位，A1 实测环绕地址 254/255 即 word）；语义 = 该张量在 bank 内的
     **静态分配上界**（三规模共用一份 YAML，故 length 必须是上界而非动态值）。
     `experimental_unroll: true` 算子 **length 必填**；缺省 → `TYPE_LAYOUT_UNSUPPORTED`。
     **实际消耗按 role/stride 语义分算（v4）**：stride=1 输入/输出张量 = `N_eff = n_rows/4`
     words；**stride=0 驻留参数与常量按驻留语义计耗**（V1：每个驻留标量 1 word），
     **不得统一按 `n_rows/4` 判定参数/常量**——消耗越出 length →
     `TYPE_LAYOUT_UNSUPPORTED`。存量 36 份未请求 YAML 不做要求（兼容由 §B.4-5 锁定）。
     G-addr 的 LIVE 越界拒绝在**最大声明规模**上判定。
   - **FILL/DRAIN 受控允许**：FILL/DRAIN 拍的烘焙地址允许 mod depth 环绕（A1 已实锤
     254/255 = (0+1·(j−2)) mod 256），**前提是其读数不进入任何 LIVE 消费链，且不污染有效
     输出**——证明义务由三区比对承担：非目标区零违例 + 有效写行数与产物 vout0 vld 计数互校
     （沿用 A1 机制）。
   - **写侧无任何豁免**：所有写事件落点必须 ⊆ 输出 tensor 声明区；非目标写一律违例
     （三区 zone3 语义，此处明确不得豁免）。
   - **LIVE 寻址越界拒绝（v4：先未取模判定，再编码）**：LIVE 区间 `0 ≤ j < N_eff` 内任何
     读/写地址，先在**未取模**形式 `orig_offset + stride·j` 上判定 ⊆ 对应张量声明区，
     越出 → G-addr 拒绝；`mod depth` 仅作用于编码层（只对 FILL/DRAIN 环绕有意义），
     **不得用取模后的地址通过合法性检查**。
   - **读侧邻居落入说明（hco notes-6）**：紧排布局下 FILL/DRAIN 环绕读地址可能恰落入同 bank
     另一张量的声明区——读不污染有效输出（三区机制不抓读侧），属**允许行为**，成文以免
     后续审查反复。
