# 人机协作分工指南 (硬件架构师 + 大模型)

> 你的角色: 硬件架构师 (提供物理真相 + 验收结果)
> 大模型角色: 软件实现者 (写代码 + 写测试 + 重构)

---

## 一、能力边界总览

### 大模型做得好的 ✅
| 能力 | 示例 | 质量 |
|:--- |:--- |:--- |
| Pydantic 数据模型 | HardwareSpec 类定义 | ★★★★★ |
| 算法翻译为代码 | 你说"RAW公理"→ 我写 Z3 代码 | ★★★★☆ |
| 测试脚手架 | conftest, mock, pytest | ★★★★★ |
| 模式复用 | sin 模板写好后，批量生成 cos/exp/log | ★★★★★ |
| 代码重构 | 提取公共基类、消除重复 | ★★★★★ |
| 文档生成 | ADR、设计报告、README | ★★★★★ |

### 大模型做不好的 ❌
| 风险 | 具体表现 | 为什么 |
|:--- |:--- |:--- |
| **物理时序正确性** | 把 FPADD=3 拍写成 2 拍 | 大模型不理解硬件物理 |
| **浮点精度** | Horner 展开项的系数精度丢失 | IEEE 754 舍入不可推理 |
| **41-bit 位域** | bit[3:0] 和 bit[4:1] 搞混 | off-by-one 是大模型高频错误 |
| **跨模块状态** | SMT 输出的 exclusions 在传到 Layout 时丢了一个 | 上下文太长会遗漏 |
| **硬件隐含约束** | 某些 IQ 不能同拍发射（你知道但没写在文档里） | 大模型只能用文档中的信息 |

| 任务 | 谁做 | 为什么 |

### Sprint 3: SMT 合成 ★最关键

| 任务 | 谁做 | 为什么 |

### Sprint 4-6: 编排/布局/E2E

## 三、你的核心工作模式

### 你（硬件架构师）只负责 3 件事

```
1. 提供物理真相 (不可替代)
   → hw_params.yaml 的数值
   → 41-bit 位域排列
   → 公理的物理语义
   → Horner 系数

2. 验收正确性 (不可替代)
   → 跑仿真器对比
   → 检查数值是否 bit-perfect
   → 确认时序是否符合硬件行为

3. 架构决策 (不可替代)
   → Bank 分配用方案 B+ (已决策)
   → Lowering 用大模型+冻结 (已决策)
   → 新的硬件特性怎么处理 (ADR)
```

### 大模型负责其他所有事

```
→ 写全部 Python 代码
→ 写全部测试
→ 重构和文档
→ 批量扩展相似算子
→ 维护 Git 提交规范
```

## 四、怎么给大模型足够的信息

### 好的指令 ✅ (大模型能做好)
```
"FPADD 延时是 3 拍，FPMUL 延时是 3 拍，UR_READ 延时是 1 拍。
 请实现 add_raw_constraints() 函数，当 op_j 依赖 op_p 时，
 断言 T_j >= T_p + latency[p.type]。"
```
→ 信息完整、规则明确、可机械实现

### 坏的指令 ❌ (大模型会出错)
```
"帮我实现 SMT 合成引擎。"
```
→ 太模糊，大模型会编造物理约束

### 黄金模板: 给大模型分配任务的格式
```
【物理约束】(你提供)
  FPADD = 3 拍, 同 Bank 同拍不能两个 UR_R

【要实现的函数】
  add_rr_conflict_axiom(solver, ops, spec)

【输入】
  solver: Z3 Solver
  ops: [MIROp(id=0, iq_type="UR_R", bank_src=?), ...]
  spec: HardwareSpec

【期望行为】
  同 Bank 同拍有两个 UR_R → Z3 不允许

【测试用例】
  两个 UR_R 都在 Bank0 同拍 → 必须 UNSAT
```

## 五、质量把控: 3 道防线

### 防线 1: 大模型自检 (写完就跑 pytest)
→ 覆盖编码错误、类型错误、逻辑明显错误
→ 大模型自己能发现的问题

### 防线 2: 验证工具链 (SMTOutputVerifier + StreamScanner + ConstraintChecker)
→ 覆盖物理约束违反、冲突遗漏
→ 自动化检测，不依赖人眼

### 防线 3: 你的仿真器 (Bit-Perfect 对比)
→ 终极物理真相
→ 只有你能运行和判断
→ 是每个 Sprint 的最终验收标准

```
大模型写代码 → [pytest] → [验证工具] → [你的仿真器]
  如果过了三道防线，代码就是正确的。
  如果没过，你只需要告诉大模型"哪个测试失败了，错误信息是什么"。
```
