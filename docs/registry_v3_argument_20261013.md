## 2. 论证 A：协议时序公式的 II 独立性（INIT_PAD / TERM_PHASE / ISSUE_TOTAL / 断言形式 / 投影两则）

### 2.1 命题

v2 六条记录的已证边界由「add，II=2」扩展至「unroll 展开形态 II∈{2,3,6}，
含多槽队列（fpadd 单/三槽、fpmul 双槽单单元/三槽）」。**II=1（flat）与
压缩行（loops≥1）仍在外，不动。**

### 2.2 论证（RTL 文本 + 发射不变量，不引用被验 trace）

三条公式的 II 依赖项为 `skip*II + 1`（INIT_PAD）与 `II*R_q`（TERM_PHASE /
ISSUE_TOTAL 体内）。论证归约链：

**① II 在硬件中不存在。** smi_iq_iic.v 参数表仅 EN_LOOPS / BITS_LOOPS /
LOOPS_MSB_BIT（:33-35）；全文无 II 寄存器、无 II 参数、无 II 分支——
IQ 侧时序完全由指令字字段与计数器驱动【源码】。

**② l_init 以编码值形态进入硬件。** `w_loops = w_rdi_data_sel[10 -: 10]`
（:253，10 bit 字段译码）；LOOPS 回放路径（:828-838）对
`EN_LOOPS && w_loops >= 'd1` 的行逐拍 `r_loops_cnt+1` 并抬
dly_data_valid，至 `r_loops_cnt == w_loops`（:1202-1203）退出清零——
**回放拍数 = 编码的 w_loops 值本身**，硬件从不计算 skip·II+1【源码】。
该编码值由发射侧写入：INIT 行 header `LOOPS = l_init`，l_init 由注册表
公式求值（emit_expected_fire_sequence.py:127/:159，skip 由该队列 t 集合
独立重算，不读产物常数）【源码】。

**③ II·R_q 以行数形态进入硬件。** 普通行路径（:841-862）每取指一行发一拍
（dly_data_valid<=1、rdi_addr+1）——**拍数 = 行数**；行数不变量
`L_q = II·R_q + 2` 是发射侧结构性质（stage_partition.py:88；
PROJ_FETCH_UNROLL 行数恒等式），逐次发射由 manifest 自洽机检
（queue_spans == 实发行数）【源码】【机制】。

**④ TERM 补拍与 ISSUE 偏移为结构常量。** dly_data_valid 是 output reg
（smi_iq_iic.v:96，全文件赋值均在时钟块内非阻塞 <=）→ 采样相位 +1；
TERM 行经 :662（embed≠7）→ :671（case 3'd0）→ :693（dly<=1）在
fetch+1 拍产恰 1 拍——两者均不引用 II【源码】（v2 记录出处原样成立）。

**⑤ 归约结论。** 三条公式在任意 II 下成立 ⟺ 发射侧正确编码
l_init = skip·II+1 且行数满足 L_q = II·R_q+2 ⟸ 发射不变量逐实例机检 +
硬件计数路径 II-无感（①-④）。**II 的数值不进入任何硬件时序路径，只进入
发射产物的字段值与行数**；因此「II=2 已证 → II∈{3,6} 扩展」不是数值外推，
而是同一结构命题在已枚举实例上的机检确认。多槽同理：槽序改变的是
t 集合（→ skip、R_q、行型），回放/发射硬件路径与槽数无关（「垫拍与槽数
无关」结构命题，v2 已证，两新形态的三类槽结构复验该命题成立——机检断言
(iv) 的形式继承）。

**⑥ 边界保持。** 上述归约对 flat（II=1，经 embed 循环路径 :662/:671 而非
普通行路径）与压缩行（loops≥1，经 :828 回放路径发射多拍/行）**不成立**——
两者的取指/发射投影是不同规则（v2 PROJ_FETCH_UNROLL 边界原文）。
II=1 形态继续不得引用 ISSUE_TOTAL_FORMULA 等条（v2 既有挂账不动）。

## 3. 论证 B：公式语义冻结（最终公式文本 / 有序 AST / 逐节点舍入顺序 / 独立参考）

### 3.1 为什么「代数等价」不足为凭

fp32 乘法不满足结合律：addcmul 步①首发实证——遗留文本 `((value·t1)·t2)`
与 DFG 折叠序 `((t1·t2)·value)` 结合序分歧，两序在 fp32 下逐位结果可不同。
因此「语义冻结」的对象必须是**特定的求值序**，不是等价类。用户裁定原文：
「应冻结调整后的公式、逐步 fp32 运算顺序及独立参考，不能只写"代数等价"。」

### 3.2 冻结机制（机器检查，非 trace）

1. **最终公式文本**：以提交态 op yaml 为唯一源（sha256 锚定，见 v3 记录
   provenance）。addcmulu 的调整后文本 `x + t1*t2*value` 于 c0ba5f3 提交，
   遗留 addcmul.yaml（((value·t1)·t2) 序）冻结登记不修改、不入本边界。
2. **有序 AST**：`parse_ordered_formula` 产生保序 AST，其 canonical digest
   写入 stage_manifest hashes.ordered_ast，验包时重算比对
   （check_stage_manifest.py:147-150）——公式/张量名任何漂移即 RED【机制】。
3. **逐节点舍入顺序**：fp32 语义 = 每 AST 节点一次舍入、按 AST 求值序
   依次求值。三层签名互等机检（sympify 同树 ∧ 共享 DFG ∧ 文本序==折叠序，
   addcmul 步①）保证「文本序 = 调度折叠序 = 参考求值序」同一。
   各算子求值序（v3 FORMULA_SEMANTICS_* 记录 value 逐字冻结）：
   - add：`y = x + other`（单节点）。
   - scale_sum：`s = x + other; y = alpha * s`（加先乘后，驻留标量）。
   - horner_v3u：`m1=c0·x; a1=m1+c1; m2=a1·x; a2=m2+c2; m3=a2·x; y=m3+c3`
     （6 节点严格串行）。
   - addcmulu：`m1=t1·t2; m2=m1·value; y=x+m2`（对齐后文本序，
     与遗留 ((value·t1)·t2) 序逐位可区分，两者不得互称等价）。
4. **独立参考**：C-H 公式驱动参考（horner 步④ bd2ed7b 通用化）按
   manifest 记录的公式原文重算有序 AST fp32 序列，与 HBM 窗/golden UR
   三方对账——参考的消费路径不含算子名/张量名特判【机制】。

### 3.3 边界

公式语义冻结绑定「该 yaml 配置 × 已测规模集合」（v3 各记录
proven_boundary 逐项列举）；不覆盖同名算子的其他文本变体，不宣称任意
公式文本经前端/lowering 后语义均保留（用户裁定：该全称**尚未成立**——
三因子乘积需要配置级结合序对齐即反例，前端表达与 lowering 之间仍有约束）。

## 4. 必答项①：放置漂移与公式冻结的关系

**命题**：求解器放置漂移不威胁协议公式冻结，因为两者作用在不同层面。

1. **分层**：协议公式是队列级函数 f(skip, II, R_q)（§2），其输入全部由
   该队列自身 t 集合独立重算（emit_expected_fire_sequence.py:14 明示
   「不读产物的常数」）；放置选择（哪些队列存在、各行落在何槽/何单元）
   改变的是 t 集合与队列集合，不改变 f 本身【源码】。
2. **漂移实证范围**：addcmulu 登记三实例——A（18 队列，span≤3，V1 链
   主流 ~15 进程）、B（17 队列，单进程）、C（17 队列，ur-r2 span=4，
   统一链两进程）；II 与 L_q 结构不变，逐拍公式/三区/写账/C1C2C3 判据
   **实例不变**（VARIANCE.md 2026-10-12 补遗）。
3. **冻结的是规则不是放置**：v3 PLACEMENT_DRIFT_POLICY 冻结的命题 =
   「允许资源放置变化；每个实例独立生成期望并验证；正确性判据实例不变；
   一致性陈述限已实测进程集合」。近壁稳定性（n=156 五进程逐字节一致）
   是实测性质，**不作为确定性承诺冻结**——「跨进程/跨代码路径逐字节
   确定性」继续禁称。
4. **对公式的回写保护**：若未来某实例的 trace 与冻结公式不符，处置 =
   PER_BEAT_PROTOCOL_MISMATCH（铁律既有），不得回改常数拟合；放置漂移
   不构成改常数的理由。

## 5. 必答项②：分段决策实例相关性 + 容量口径

1. **分段是发射后处理**：每个分段是独立程序（各有 INIT/BODY/TERM），
   协议公式段内适用（§2 归约不受影响）；段边界由该次实际调度的队列
   跨度与容量墙共同决定——实例 A（全 span≤3）→ m_max=39；实例 C
   （ur-r2 span=4）→ m_max=38。两实例的 L_q=3·(m+span_q)+2 均逐字节
   成立【机制】。
2. **合法判据（用户裁定原文三点）**：①各段并集覆盖同一逻辑迭代集合；
   ②段间地址接续正确（C3 写集对账）；③各段容量合法（≤128 行/队列）。
   39+1 与 38+2 均满足三点、均全链 GREEN——**两形态都正确**。
3. **冻结对象**：决策规则（上三点判据 + 由实际调度定边界）与实例证据，
   **不冻结「n=160 必须切成某一种形状」**（SEGMENTATION_DECISION_RULE
   value 逐字写入该禁令）。
4. **容量口径**：容量墙 128 行/段是硬件常数（smi_top.v:22 IQ 深度）；
   单段迭代容量是已校准实例的实测结果（add 240 / scale_sum 240 /
   horner_v3u 68 / addcmulu 156，统一链分段边界实测区间 38–39），
   更广适用性须有额外依据；构造预测未校准禁用于准入
   （CAPACITY_MEASURED_SCOPE 逐字冻结）。
