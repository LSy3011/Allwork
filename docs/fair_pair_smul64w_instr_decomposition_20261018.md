# 公平对照 COMPUTE 指令足迹静态拆解：Δ11 行 / Δ15 beats 归因（2026-10-18）

依据：用户 2026-10-18 四步序之 **② 静态拆解多出的 11 条指令、15 个 beat——
判断来自 INIT、延迟、终止还是其他发射差异；本轮先不优化**。
对象：公平对照组合程序（commit d59111a，设计
`docs/fair_pair_scalar_mul_64w_design_20261018.md`，归档
`verification_v2/artifacts/fair_pair_smul64w_20261018/`）stage_1 的
十三对队列描述文件 `iq_inst_*_subq0.txt`（A 手写 vs B 编译器）。
**范围：纯静态拆解与角色归因；不做任何优化，不做字段语义断言。**

## 1. 结论先行

- **Δ11 行全部来自 INIT 角色行**：B 编译器 13 队列统一三行形态
  [INIT, BODY, TERM]；A 手写 11 队列为两行形态 [BODY′, TERM]（无独立
  INIT 行），2 队列（rtovr-35、ur-w0）为三行（含首行配置行，角色同 INIT）。
  11 个两行队列 × 每队列缺 1 行 INIT = **+11**，算术闭合。
- **无独立延迟填充行、无额外终止行**：TERM 两侧 13/13 队列成对存在
  （12/13 逐字节一致，ur-w0 差一个低字段）；两侧均未观察到纯延迟/空转
  填充行。
- **Δ15 beats = 行差 × 每行 beat 数**：每行 beat 数（1 或 2）由队列指令
  字节落位是否跨 16B AXI beat 边界决定，**同一队列两侧完全相同**
  （13/13 实证）。分解式：7 个 1-beat 队列 ×1 + 4 个 2-beat 队列 ×2
  + 2 个零行差队列 ×0 = **+15**，算术闭合。
- **195 拍 = (54−39) × 13** 在逐队列粒度闭合（§4）。
- BODY 角色两侧同在，但载荷字段编码多数不同（§5）——属**发射参数编码
  差异，不改变行数与 beats**；端到端行为等价已由两链 8/8 SMC bit-exact
  验收覆盖。

## 2. 方法

- 数据源：两变体 `smi_iq_inst/stage_1/iq_inst_*_subq0.txt` 各 13 个
  （26 个文件 sha256 见 §7 附录）。
- 头部字段：`IQ_BITS`（指令位宽）、`IQ_BYTE_START/END`（在 IQ 行内的
  字节区间）、`AXI_BEAT_ADDR`（该行装载占用 beat 地址列表，逗数数即
  beats/行）、`INST_LINES`（逻辑指令行数）。
- 每行 beat 数公式（13 队列全验）：
  `beats/行 = floor(IQ_BYTE_END/16) − floor(IQ_BYTE_START/16) + 1`
  （IQ 行 = 128B = 8 个 16B AXI beat；指令字节区间跨 beat 边界则 2，
  否则 1）。例：fpmul 47..53 跨界 → 2；rtovr-14 346..351 不跨 → 1；
  ur-w0 156..165 跨界 → 2。
- 角色判定：逐 INST 行载荷字节对照（A 末行↔B 末行、A 首行↔B 次行等），
  结合 b1 探针已解码的编译器平坦形态 INIT(LOOPS=5)/BODY(VLD=1,LOOPS=63)
  /TERM(JUMP=1) 标记。

## 4. 角色归因（逐项回答「INIT / 延迟 / 终止 / 其他」）

**B 编译器**：13 队列统一 [INIT, BODY, TERM] 三行（level-0 平坦压缩流
既有形态，b1 探针已解码：INIT 携带 LOOPS=5 启动配置，BODY 携带
VLD=1/LOOPS=63 主流水，TERM 携带 JUMP=1）。

**A 手写**：

- 11 个两行队列 = [BODY′, TERM]——**无独立 INIT 行**；循环计数等参数
  直接编码进 BODY′ 字段。255w 先例（r2 case `mul_scalar_8smc_v3_fpga_
  v422_255w_20260828_111130` fpmul txt）实证手写侧迭代计数随规模缩放在
  **低位字段**：64w=`…010004E00C00` vs 255w=`…010010D00C00`
  （0x4E=78 ↔ 0x10D=269，差 191 = 迭代数差 255−64）；而首拍 `3F00…`
  **与规模无关**（255w 先例同为 `3F`）——A/B 首拍逐字节一致不意味着
  字段语义相同，B 侧 LOOPS=63 解码自编译器 physical_instructions.json，
  A 侧字段语义不做逐位断言。
- 2 个三行队列（rtovr-35、ur-w0）= [首行配置, BODY′, TERM]——首行
  角色同 INIT（手写侧这两个队列也发独立配置行），故行数差为零。

逐角色结论：

| 归因项 | 结论 | 证据 |
|---|---|---|
| **INIT 行** | **11/11 行差全部在此**：B 每队列 1 行 INIT；A 仅 rtovr-35/ur-w0 有对应配置行 | 13 队列行数表 + fpmul/rtovr-14 逐行对照 |
| **延迟填充行** | **零贡献**：两侧均无独立延迟/空转行 | 全 26 文件 INST 行逐行角色检查 |
| **终止行（TERM）** | **零贡献**：13/13 成对存在；12/13 末行逐字节一致；ur-w0 末行差一个低字段（`…00030000001000` vs `…00030000000000`） | 末行批量字节对照 |
| **其他发射差异** | **不改变行数/beats**：BODY 载荷字段编码多数不同（仅 ur-r0/ur-r1 逐字节一致，11/13 有字段差，例 rtovr-14 A=`8001F802003D…` vs B=`8001F800003F…`）；角色相同 | 首行↔次行批量字节对照 |

**拍数闭环**：Δ15 beats × 13 拍/beat = +195 拍 = 实测 stage_1 装载差额
（507→702）= 实测 T_total 差额（1713→1908），与取数表（归档 README §4）
逐项一致。

## 5. 性质声明（防过度解读）

- 本拆解只做**行数/beats/角色**归因；BODY′ 与 BODY 的字段编码差异
  **不做 ISA 字段语义断言**（未逐位对照指令集手册；其行为等价已由两链
  8/8 SMC、verify_ddr、独立 IEEE 参考三重 bit-exact 验收覆盖）。
- B 的 INIT(LOOPS=5) 与 A 对应参数如何编码进 BODY′（或是否依赖队列
  缺省）属字段语义问题，超出本轮拆解范围。
- 「编译器每队列多一行 INIT」是**发射形态差异**（平坦三行式 vs 手写
  紧凑两行式）的静态事实；是否可优化、优化是否合法，**本轮不评估**
  （用户令：先把「正确生成的代价」解释清楚，再决定是否值得优化指令
  足迹）。
- 执行观测口径不变：trig→done 144=144 为含轮询与应答的**完成观测窗口
  上界代理**，本拆解不提供拍级执行差异证据，也不与之矛盾。
